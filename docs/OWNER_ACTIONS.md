## ⚠️ BLOCKING (must be done before any public user has access)

### O-1 · TOTP 2FA — Enroll SUPER_ADMIN before first real login
The `requireMfaEnrolled` middleware blocks `/admin/*` until the SUPER_ADMIN has enrolled TOTP. Steps:
1. Log in as SUPER_ADMIN (triggers force-password-change)
2. Change password at `/force-change-password`
3. Navigate to `/account/security/2fa-setup`
4. Scan QR code with Google Authenticator / Authy / similar
5. Enter confirmation code → download recovery codes → store securely
6. Verify you can reach `/admin`

### O-2 · Set `MFA_ENCRYPTION_KEY` in production `.env`
Generate with:
```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```
Add to `server/.env` as `MFA_ENCRYPTION_KEY`. Never commit this value. Never log it.

### O-3 · Remove `SUPER_ADMIN_INITIAL_PASSWORD` from `.env` after first login
This variable is only needed for bootstrap. After the SUPER_ADMIN's first successful login and password change, delete it from `.env`.

### O-4 · Real institution data
`khenchela-institutions.json` is a template with placeholder data. Before launch:
- Verify every institution entry (name, address, phone, coordinates)
- Set `status: "VERIFIED"` and add a `sourceNote` for each verified entry
- Remove or mark draft any unverified entries

### O-5 · SMTP configuration
Configure a production email sending service:
- Set `MAIL_ENABLED=true`
- Provide `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`
- Configure SPF, DKIM, and DMARC records on your sending domain
- Free webmail (Gmail, Yahoo) is not suitable for production

### O-6 · Production domain and sitemap
Once the production domain is confirmed:
1. Update `APP_BASE_URL` in `.env`
2. Run `npm run sitemap:generate` to regenerate `public/sitemap.xml`
3. Submit the sitemap to Google Search Console

## P1 (should be done soon after launch)

### O-7 · Privacy policy — legal review
The privacy policy at `/privacy` references Law 18-07. Before public launch, have a qualified Algerian legal professional review:
- Data controller identification (legal name, address)
- Contact details for privacy requests
- Data retention periods
- Cross-border transfer clauses (if any hosting is outside Algeria)

### O-8 · Terms of use — legal review
Similar to O-7. The terms at `/terms` need a legal name and governing jurisdiction confirmed.

### O-9 · Contact page — real contact details
The `/contact` form stores messages in the database. The owner needs to:
- Monitor the admin inbox at `/admin` regularly
- Add a real support email or phone number if desired

### O-10 · Analytics decision
No analytics are currently installed. If the owner wants analytics:
- Must assess GDPR / Law 18-07 compliance
- Must update the privacy policy accordingly
- Recommend self-hosted (Matomo/Umami) or European providers

### O-11 · Hosting location
Law 18-07 may require data to be stored within Algeria. Consult legal counsel before choosing a hosting provider outside Algeria.

### O-12 · App store submission (optional)
If submitting to Google Play Store as a TWA:
- Provide a verified domain at `/.well-known/assetlinks.json`
- Apple App Store requires native code — PWA via Safari only

### O-13 · Logo / icon quality
The current `public/logo.jpg` is 720×586 px (72 dpi). For sharp icons at 512×512 and above:
- Provide an SVG or PNG ≥ 1024×1024 px
- Then re-run `npm run icons:generate`

### O-14 · External penetration test
Strongly recommended before accepting real patient data. Use a qualified security firm.

### O-15 · FAQ and About page — owner content
The `/faq` and `/about` pages contain accurate but generic content. The owner should add specific information about:
- Who built/operates the platform
- Physical address (required by Law 18-07 for data controllers)
- Any partnerships with the Ministry of Health or DHW Khenchela
